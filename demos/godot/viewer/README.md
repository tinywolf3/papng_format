# PAPNG Viewer

Godot 4.7.2 기반의 독립 실행형 이미지 뷰어입니다. Linux·Windows·Android에서 PAPNG, PNG, APNG 파일을 열 수 있습니다. 포맷 버전은 PAPNG 1.1, 앱 버전은 0.2.0입니다.

## 이미지 보기

`열기` 또는 **파일 → 열기**에서 이미지를 선택합니다. 데스크톱에서는 파일을 창에 끌어 놓거나 실행 파일에 파일 경로를 전달할 수도 있습니다. 파일을 열면 바로 재생을 시작합니다. 일반 PNG는 정지 이미지로 표시하며, 애니메이션은 파일의 반복 횟수와 프레임 제어를 따릅니다.

- 재생·일시정지, 처음으로, 다음 방문, 프레임 탐색과 메타데이터의 클립 선택을 지원합니다.
- 휠 또는 `+`/`-`로 확대·축소하고 드래그로 이동합니다. 터치 드래그와 확대 제스처도 지원합니다.
- **색상 → 마스크 색상**에서 마스크 번호와 이름을 확인하고 색상 선택기로 색을 시험합니다. 선택한 색의 H와 원본 평균색의 H 차이를 해당 마스크의 HSV 변화량으로 적용합니다. ΔS·ΔV 입력은 −1~+1 가산 차이이며 결과를 0~1로 제한하고 픽셀별 알파를 유지합니다.
- **마스크**는 선택된 마스크의 합성 후 보이는 영역을 강조합니다. 색상 대화상자를 사용하기 전에는 모든 마스크를 표시합니다. 이 강조 표시는 기본 이미지에 적용됩니다.
- **힌트**는 바운딩 박스·피벗·캔버스 경계와 출력 크기·픽셀 배수 힌트를 보여 줍니다. 출력 크기·배수는 설명으로 표시하고 원본 픽셀 좌표계를 유지합니다.
- **소켓**은 현재 프레임의 소켓 위치·이름·회전 방향을 보여 줍니다.
- **파일 → 파일 정보**에서 원본 종류, 경고와 JSON5 메타데이터를 볼 수 있습니다.

마스크의 원본 평균색은 전체 프레임의 마스크 대상 원본 픽셀을 알파 가중 평균한 RGB로 계산합니다. 무채색은 기준 H=0으로 계산하며 S/V를 올려 색을 입힐 수 있습니다. 색상 변경은 재생을 멈추고 0번 프레임부터 다시 복원합니다. 클립 선택 시에는 해당 클립의 시작 위치까지 복원합니다. 변경은 미리보기 상태이며 원본 파일에 저장하지 않습니다.

### 단축키

- `Ctrl+O`: 파일 열기 / `Ctrl+M`: 마스크 색상 / `Ctrl+L`: 부속 파일 열기 / `Ctrl+B`: 배경 설정
- `Space`: 재생·일시정지 / `Home`: 처음으로 / `→`: 다음 방문
- `M`: 마스크 강조 / `H`: 헤더 힌트 / `S`: 소켓 표시
- `F`: 화면에 맞춤 / `1`: 원래 크기 / `+`, `-`: 확대·축소

macOS 키보드에서는 Ctrl 대신 Meta도 인식하지만 macOS 배포 대상은 포함하지 않습니다. Android에서는 툴바와 메뉴로 같은 기능을 사용할 수 있습니다.

## 배경

툴바의 **배경**, **보기 → 배경**, 또는 `Ctrl+B`로 설정합니다. 기본은 투명도를 확인하는 **체크무늬**이며 **단색**과 색상 선택기를 사용할 수 있습니다.

PAPNG·PNG·APNG를 연 뒤 **이미지…**로 PNG·JPEG·WebP·BMP·SVG 배경을 불러옵니다. APNG/PAPNG를 배경으로 선택하면 PNG의 기본 이미지를 정지 배경으로 사용합니다. Android에서도 시스템 파일 선택기를 사용합니다.

- **X/Y**는 PAPNG 왼쪽 위를 기준으로 배경 이미지 왼쪽 위의 픽셀 좌표입니다. 음수와 소수도 사용할 수 있습니다.
- **배율**은 가로세로 비율을 유지하며, 100%는 배경 원본 1픽셀이 PAPNG 1픽셀입니다. **이미지에 맞춤**으로 현재 PAPNG 캔버스 안에 들어오도록 가운데 배치합니다.
- **불투명도**는 이미지 자체의 알파와 함께 적용됩니다. **이미지 표시**를 끄면 설정을 유지한 채 숨기고 **제거**하면 배경 이미지를 해제합니다.

배경은 PAPNG와 함께 확대·축소·이동하고 재생 중에도 유지됩니다. PAPNG 캔버스 밖의 배경도 뷰 영역 안에서 표시하므로 장면 위에 이미지를 놓아 볼 수 있습니다. 배경을 바꿔도 애니메이션 재생 위치나 마스크 색상은 바뀌지 않습니다. 다른 파일을 열어도 배경과 설정을 유지하며, 앱을 종료하면 초기화됩니다. 원본 파일에는 저장하지 않습니다.

배경 파일은 최대 64 MiB, 디코딩한 이미지는 32메가픽셀까지입니다. 긴 변이 4096픽셀을 넘으면 표시용 텍스처를 축소하지만 위치·배율의 기준은 원본 이미지 크기를 유지합니다.

## 소켓에 부속 연결

소켓이 있는 기본 이미지를 열고 **부속 → 소켓에 연결할 파일**로 부속 이미지 하나를 선택합니다. 소켓 선택 목록에서 결합 위치를 바꿀 수 있습니다. [socket-buddy.papng](../../../samples/socket-buddy.papng)와 [socket-wand.papng](../../../samples/socket-wand.papng)가 예제입니다.

부속의 피벗을 부모 소켓에 맞추고 소켓의 회전각을 적용하여 부모 위에 그립니다. 피벗이 없는 부속은 `(0, 0)`을 사용합니다. 부모와 부속은 각자의 지연·프레임 제어로 독립 재생하고, 재생·일시정지·처음으로 조작은 함께 적용합니다. 부모 재생이 끝나면 부속도 멈춥니다. 부속의 마스크 색도 대화상자에서 별도로 변경할 수 있습니다.

현재 범위는 **부속 하나의 미리보기 결합**입니다. 여러 단계의 결합, 프레임 동기화 규칙, 합성 결과 저장과 장면 편집은 포함하지 않습니다.

## 플랫폼별 실행과 파일 연결

빌드 출력은 저장소의 `builds/<platform>/papng-viewer/`에 생성됩니다. Linux는 실행 파일과 tar.gz, Windows는 실행 파일과 zip, Android는 APK를 제공합니다. 설치 스크립트를 사용할 때는 압축 파일 전체를 풀고 실행합니다.

### Linux x86_64

`builds/linux/papng-viewer/papng-viewer.x86_64`를 실행합니다. 관리자 권한 없이 `builds/linux/papng-viewer/install.sh`를 실행하면 사용자 앱 메뉴와 `.papng` 연결을 등록합니다. `xdg-utils`와 `desktop-file-utils`가 필요합니다. 기본 설치 위치는 `~/.local/share/papng-viewer/`이며 `XDG_DATA_HOME`을 따릅니다.

PNG/APNG는 이 앱으로 열기 후보에 추가하고 기존 기본 앱은 유지합니다. 제거는 설치된 `uninstall.sh`로 수행합니다. 설치 전에 사용하던 PAPNG 기본 앱이 있다면 복원합니다.

```sh
builds/linux/papng-viewer/papng-viewer.x86_64 -- /path/to/image.papng
```

### Windows x86_64

`builds/windows/papng-viewer/papng-viewer.exe`를 실행합니다. 같은 폴더의 `install.ps1`은 사용자 프로필의 `%LOCALAPPDATA%\PAPNGViewer`에 설치하고 HKCU의 파일 연결과 시작 메뉴 바로가기를 등록합니다. 관리자 권한은 필요하지 않습니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1
```

이미 다른 기본 앱이 지정되어 있다면 파일의 **연결 프로그램 → PAPNG Viewer → 항상**을 선택합니다. Windows의 기본 앱 선택을 강제로 우회하지 않습니다. 제거는 설치 폴더의 `uninstall.ps1`을 실행합니다. Windows 배포 파일은 코드 서명하지 않았습니다.

### Android

`builds/android/papng-viewer/papng-viewer-debug.apk`는 로컬 테스트 키로 서명한 설치용 APK입니다. Android 7.0/API 24 이상, arm64 또는 x86_64, OpenGL ES 3.0이 필요합니다. 스토어 배포용 서명은 별도로 구성해야 합니다.

앱의 **열기**는 시스템 파일 선택기를 사용합니다. 파일 관리자에서 **다른 앱으로 열기** 또는 **공유**로 PAPNG Viewer를 선택할 수도 있습니다. 파일 제공자가 전달한 `content://` 읽기 권한을 사용하며 전체 저장소 권한은 요청하지 않습니다. 파일 제공자가 PAPNG를 `application/octet-stream`으로 보고하는 경우에도 열기 후보에 표시됩니다. 확장자별 기본 연결 제공 여부는 파일 관리자에 따라 다릅니다.

## PNG·APNG 가져오기

파일의 실제 PNG 청크를 검사합니다. 일반 PNG/APNG는 별도의 중간 파일을 쓰지 않고 마스크·제어·소켓이 없는 기본 PAPNG 재생 모델로 정규화합니다.

- PNG의 팔레트·그레이스케일·16비트 등 Godot PNG 디코더가 지원하는 원본을 RGBA8로 정규화합니다.
- 정지 PNG는 한 프레임, 한 번 재생으로 취급합니다.
- 일반 APNG의 `delay_den=0`은 100, `delay_num=0`은 가져오기 기본값 10 ms로 변환합니다.
- PAPNG의 0 지연은 합성에 사용하고 출력하지 않습니다. 무한 0 지연 루프도 UI를 막지 않도록 나누어 처리하며 재생·일시정지로 중단할 수 있습니다.
- 원본 파일은 수정하지 않습니다. 색상 프로파일을 변환하는 전문 색상 관리 뷰어는 아닙니다.

## 개발과 빌드

필요 도구:

- Godot **4.7.2 stable**과 같은 버전의 공식 export templates.
- Python 3.10 이상.
- Android 빌드: JDK 17, Android SDK platform 36, build-tools 36.1.0 및 Godot 템플릿이 지정한 Gradle 의존성. 최초 빌드에는 네트워크가 필요합니다.

Linux에서 세 플랫폼을 교차 빌드합니다. 도구 경로가 기본 위치와 다르면 `GODOT_BIN`, `ANDROID_HOME`, `JAVA_HOME`을 지정합니다. 설치된 Godot 전역 편집기 설정은 바꾸지 않고 `builds/linux/viewer-tools/` 안에 전용 설정·캐시·템플릿을 둡니다. Godot의 프로젝트 가져오기 캐시 `.godot/`는 일반적인 프로젝트 내부 캐시이며 Git에서 제외됩니다.

```sh
python3 tools/native/build.py linux windows android --templates /path/to/Godot_v4.7.2-stable_export_templates.tpz
# 이후에는 저장한 템플릿을 재사용합니다.
python3 tools/native/build.py linux windows android
```

Android Gradle 프로젝트도 `builds/android/papng-viewer/gradle/` 아래에 생성됩니다. Android 파일 연결 필터는 `addons/android_open/`의 export plugin이 넣습니다. 생성된 AndroidManifest.xml을 직접 편집할 필요가 없습니다. 빌드 결과마다 SHA-256 파일을 생성하고 APK의 서명과 16 KiB 정렬을 확인합니다.

## 구현과 지원 범위

`core/document.gd`는 파일 파싱·가져오기, `core/player.gd`는 합성·프레임 제어·캐시, `core/session.gd`는 작업 스레드와 UI 명령 처리를 담당합니다. 색상 변경은 프레임 합성 전에 적용합니다. 이전 프레임으로 이동하면 이전 캐시 또는 0번부터, 앞으로 이동하면 순차 합성하여 복원합니다. 소켓은 표시 프레임 번호로 조회합니다.

점프 대상과 클립 시작 프레임은 캐시 잔류 우선순위를 높입니다. 캐시가 없더라도 동일한 합성 결과를 복원합니다. 랜덤 값은 재생 방문 때 새로 선택하며 복원 과정 자체에서는 랜덤을 뽑지 않습니다.

뷰어 구현의 메모리 예산은 파일·RGBA 캔버스 각각 128 MiB, JSON5 메타데이터 8 MiB, 이미지별 디코딩 캐시 32 MiB, 합성 캐시 32 MiB, 마스크 캐시 16 MiB입니다. 작업 중 버퍼·화면 텍스처 등은 별도로 필요하므로 이 수치의 합이 프로세스 최대 메모리는 아닙니다. 이 예산은 포맷 한도가 아니며 큰 리소스는 경고 또는 로딩 오류로 처리합니다. GDScript CPU 합성이므로 큰 이미지의 실시간 성능은 기기에 따라 달라집니다.

JSON5 파서는 주석·따옴표 생략 키·후행 쉼표·16진수 등을 지원하고 코드를 실행하지 않습니다. 규격대로 중복 키를 거부하며 필드별 유한수·범위 검증을 별도로 적용합니다.

Windows는 Wine에서 실행을 검증하며 실제 Windows의 탐색기·기본 앱 UI는 별도 확인 대상입니다. Android 에뮬레이터 검증은 실제 휴대폰의 GPU·파일 관리자 조합에 대한 검증을 대신하지 않습니다.
