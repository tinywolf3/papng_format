# PAPNG Pixel lab

PAPNG 1.0 리소스의 마스크 복원과 확장 재생을 확인하는 TypeScript 웹 데모입니다. [한국어 명세](../../../spec/PAPNG-1.0.ko.md)를 기준으로 구현했습니다. 라이브러리 API와 캐시 정책은 아직 실험용이며 명세의 일부가 아닙니다.

## 실행

Node.js 22.12 이상과 npm이 필요합니다. 저장소 **루트**에서 실행합니다.

```sh
npm ci
npm run dev
```

브라우저에서 `http://127.0.0.1:5173`을 엽니다. 배포 파일과 미리보기는 다음 명령으로 준비합니다.

```sh
npm run build
npm run preview
```

배포 출력은 최상단 `builds/web/viewer/`이며, 미리보기 주소는 `http://127.0.0.1:4173`입니다. 이 출력 디렉터리를 정적 웹 서버에서 제공하면 됩니다. 상대 주소를 사용하므로 하위 경로에 배포할 수도 있습니다. Worker와 샘플 로딩을 위해 `file://`로 HTML을 직접 여는 대신 HTTP(S)를 사용하세요. 명세 문서의 HTML은 생성하지 않습니다.

## 화면 사용

- 왼쪽에서 [샘플 6개](../../../samples/README.md)를 선택하거나 로컬 파일을 열고 끌어 놓습니다. 선택한 파일은 브라우저 안에서 처리하며 서버로 업로드하지 않습니다.
- 재생·일시정지·처음부터·다음 방문 버튼과 프레임 슬라이더를 사용할 수 있습니다. 표시되는 프레임 번호는 0부터 시작합니다. 슬라이더는 해당 번호로 복원한 뒤 실제 방문을 시작합니다. 0 지연 방문은 출력하지 않으므로 곧바로 다음 출력 프레임까지 진행할 수 있습니다.
- 오른쪽 팔레트에서 각 마스크의 H16(0–65535)을 슬라이더 또는 숫자로 수정합니다. 알파값과 그룹 이름도 표시합니다. 수정은 미리보기에만 적용하며 파일을 다시 저장하지 않습니다.
- 재생 중에는 팔레트 편집이 잠깁니다. 일시정지 후 색상각을 바꾸면 합성 상태와 캐시를 폐기하고 0번부터 복원합니다. 클립이 선택되어 있으면 앞부분을 복원한 뒤 해당 클립에서 다시 시작합니다.
- 클립을 선택하면 재생 구간과 반복 횟수가 적용됩니다. 바운딩 박스·피벗은 선택적으로 겹쳐 표시하며 이미지를 자르지 않습니다. 자동 배율은 출력 크기, 픽셀 배수 순으로 참고하고 화면 안에 맞춥니다.
- 캐시 사용량, 적중 횟수, 해제 횟수, 현재 합성 상태의 크기와 복원 횟수를 표시합니다. 캐시를 끄거나 예산을 바꾸어 결과와 재사용량을 비교할 수 있습니다.

## 재생 구조

UI와 Canvas 출력은 메인 스레드에서, 파일 파싱·PNG 복호화·합성·재생 상태 관리는 하나의 Web Worker에서 수행합니다. 압축 해제에는 브라우저의 `DecompressionStream`을 사용합니다. 외부 런타임 패키지는 필요하지 않습니다.

```text
로컬 파일 / 샘플
  → Worker: PNG·paEX·iTXt 읽기
  → Player: 방문의 지연 평가 → 시간이 끝나면 다음 대상 선택
  → Compositor: 필요한 프레임 복원 ↔ 상태 캐시
  → 양의 지연 방문만 RGBA 버퍼 전달 → Canvas
```

PNG 필터 0–4와 Adam7을 직접 복원하여 원본 RGBA 바이트를 얻습니다. A=1 마스크는 선곱 알파나 표시용 색 변환 이전에 해석하고, 팔레트와 S8/V8로 RGB를 복원한 뒤 APNG 합성을 합니다. `<img>`를 Canvas로 읽어 마스크 데이터를 얻는 방식은 사용하지 않습니다.

**실제 방문과 복원을 분리합니다.** 실제 방문에서는 시간을 평가하고 필요한 난수를 한 번 추출합니다. 랜덤 이동의 추출은 지연이 끝난 후입니다. 복원 중 거치는 중간 프레임에서는 시간·난수·제어·재생 횟수 처리를 하지 않습니다.

- 앞으로 이동하면 현재 상태 또는 더 가까운 캐시 상태에서 대상까지 순서대로 합성합니다.
- 뒤로 이동하면 대상의 저장 상태를 사용하거나 0번부터의 표준 합성 결과를 재구성합니다. 캐시가 있으면 가장 가까운 앞쪽 상태부터 이어갑니다.
- 자기 자신으로 이동하면 폐기하거나 다시 합성하지 않고 새로운 방문을 시작합니다.
- 클립의 시작 전 프레임도 필요하면 이미지 복원에만 사용합니다.
- 0 지연 프레임도 폐기 연산을 포함해 정상적으로 합성합니다. 출력 이미지는 갱신하지 않습니다. 유한 재생의 마지막 방문이 숨김 프레임이어도 마지막으로 출력한 이미지가 남습니다.

시간은 분자/분모를 유지하고 분모 0을 100으로 해석합니다. 양의 시간을 정수 밀리초로 반올림하여 숨김 프레임으로 만들지 않습니다. `performance.now()`에 누적한 마감 시각을 사용하고, 한 작업에서 최대 64번의 전환 또는 약 8ms를 처리한 뒤 제어권을 양보합니다. 시간 0의 순환도 취소할 수 있으며 논리적인 지연을 임의로 넣지 않습니다. 미리보기는 숨김 방문 256회 후 정지하여 무한 순환을 알립니다. 이는 파일의 프레임 수 제한이 아닙니다.

브라우저의 타이머와 화면 갱신 빈도 때문에 모든 양의 지연 방문을 실제 화면에서 구분할 수 있는 것은 아닙니다. 특히 백그라운드 탭에서는 브라우저의 타이머 제한이 적용됩니다.

## 점프 대상 우선 캐시

캐시 예산의 기본값은 **32 MiB**이며 0·4·16·32·64 MiB로 바꿀 수 있습니다. 엔트리는 대상 프레임의 합성 완료 후·폐기 전 캔버스와, 필요한 경우 `PREVIOUS` 복원을 위한 캔버스를 함께 저장합니다. 두 배열의 실제 바이트 크기를 모두 예산에 포함합니다.

현재 합성 상태는 동작에 필수이므로 캐시와 별도로 유지합니다. 캐시의 32 MiB는 프로세스 전체 메모리 한도가 아닙니다. 입력 파일, 현재 상태, 압축 해제·합성 임시 버퍼, 출력 Canvas도 메모리를 사용합니다.

정적 이동 대상, 클립 시작점, 작은 랜덤 후보 집합에 가중치를 줍니다. 실제 이동 대상으로 선택된 프레임도 우선도를 높입니다. 큰 랜덤 구간 전체를 미리 생성하거나 영구 고정하지 않습니다. 반복해서 찾는 프레임은 적중 횟수로 추가 우대를 받습니다.

퇴출 점수는 다음과 같습니다. 점수가 가장 작은 엔트리부터 제거합니다.

```text
(1 + target_priority + log2(1 + hit_count)) / (1 + access_age)
```

`access_age`는 시간 대신 캐시 접근 순번의 차이입니다. 적중 횟수와 우선도에 상한을 두어 오래 사용하지 않은 대상이 계속 남지 않게 합니다. 프레임 0, 매 16번째 프레임, 우선 대상, 실제 요청 대상은 복원 중 저장 후보가 됩니다. 한 엔트리가 예산보다 크면 캐시에 넣지 않습니다. 캐시를 모두 비워도 이미지·시간·대상 선택 의미는 같습니다.

이 정책은 첫 구현의 기본값입니다. 큰 리소스에서 측정한 결과에 따라 가중치와 중간 저장 간격을 바꿀 수 있으며 파일 포맷 변경은 필요하지 않습니다.

## 구현 위치

- [파서](../../../packages/papng/src/parser.ts): 컨테이너·CRC·확장 정보·메타데이터.
- [픽셀 복원](../../../packages/papng/src/pixels.ts): PNG 필터·Adam7·HSV 마스크.
- [재생기](../../../packages/papng/src/player.ts), [제어](../../../packages/papng/src/controls.ts), [난수](../../../packages/papng/src/random.ts): 방문·클립·프레임 제어와 정수 가중치 추출.
- [합성기](../../../packages/papng/src/compositor.ts), [캐시](../../../packages/papng/src/cache.ts): 표준 합성 상태와 바이트 예산.
- [Worker](src/worker.ts): 시간 예약, 작업 분할과 취소.
- [UI](src/main.ts): 팔레트·샘플·재생 조작과 Canvas 출력.

난수는 `crypto.getRandomValues()`에서 얻습니다. 정수 누적 확률과 거부 추출을 사용하여 범위 나머지 연산의 편향을 피합니다. 큰 32비트 구간의 가중치 합은 `BigInt`로 계산하며 구간 전체를 배열로 만들지 않습니다. 시드 저장이나 재생 순서 재현 UI는 제공하지 않습니다.

## 지원 범위와 검증

현대적인 브라우저의 Worker·Canvas·`DecompressionStream`·`BigInt`가 필요합니다. 자동 브라우저 검증은 Chromium을 사용합니다. 일반 PNG/APNG의 PAPNG 가져오기 변환, 파일 저장, 색 관리 프로파일 적용은 이 데모 범위에 포함되지 않습니다. `gAMA`·`cHRM`·`iCCP`가 있으면 색 관리 미적용을 알립니다. 애니메이션 밖의 기본 포스터는 재생 프레임에 포함하지 않습니다.

데모의 호스트 예산은 입력 파일 128 MiB, 캔버스 RGBA 한 장 128 MiB, 선택적 텍스트 메타데이터 8 MiB, JSON 중첩 128단계 미만입니다. 넘으면 이유를 표시하여 중단하거나 선택적 메타데이터만 무시합니다. PAPNG의 크기·프레임 수 한도가 아닙니다. 잘못된 마스크는 투명 소스 픽셀, 잘못된 제어는 10ms 후 순차 진행으로 복구하고 경고합니다.

```sh
npm run samples
npm run check
npm run build
npx playwright install chromium
npm run test:web
```

Chromium 설치는 처음 한 번 필요합니다. 검사에는 모든 PNG 필터·Adam7, 마스크 원본 바이트, 캐시 사용 여부에 따른 합성 일치, 앞뒤·자기 이동, RNG 추출 시점, 클립, 유한 반복, 오류 복구, 숨김 프레임 순환의 UI 응답성, 데스크톱·모바일 화면이 포함됩니다. 브라우저 보고서와 스크린샷은 `builds/web/viewer-tests/` 아래에 저장합니다.
